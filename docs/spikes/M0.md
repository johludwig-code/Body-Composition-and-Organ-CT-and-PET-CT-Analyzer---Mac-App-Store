# M0 — Spikes: runbook and results

The four spikes of plan §17. Each has a Go criterion; features start only
after all four say Go. What could be done without a Mac was done in the
cloud on 2 October 2026; everything that needs macOS, signing, the sandbox
or MPS is a numbered step to run on the Mac.

## Results so far

| spike | question | state |
|---|---|---|
| S1 | MOOSE runs offline from the bundle | **Desk part done, CPU run done (Linux).** Source read, five traps found and handled (ADR 0011), real model fetched, slimmed and run offline through the worker. MPS run on the Mac outstanding. |
| S2 | Worker inherits sandbox and folder access | Harness built (`spike_s2` job, Settings → Diagnostics). Run on the Mac outstanding. |
| S3 | Store accepts embedded Python + PyTorch | Runtime pinned and patched (ADR 0004); signing and upload outstanding. |
| S4 | Size and runtime | Size of one model measured (118 MB after slimming, `docs/benchmarks.md`); full set and MPS timings outstanding. |

### S1 in the cloud (Linux x86_64, CPU, no network)

Run as the real worker entry point, under `unshare -n` (a network namespace
with no interfaces, so any connection attempt fails), against a synthetic
192×192×100 CT phantom, model `clin_ct_organs`, from a resources folder laid
out exactly like the bundle's:

| check | result |
|---|---|
| network | none available (`unshare -n`); no `model_not_in_bundle`, no connection attempt reached the adapter's guard |
| model path | weights read from the bundle layout (`Resources/models/nnunet_trained_models`), not from moosez's package folder |
| writes into site-packages | **none** (checked with `find -newer` after both runs) — the pre-installed trainer kept MOOSE from copying it |
| output grid | size, spacing, origin and direction identical to the input CT |
| slimming | labelmaps from the slimmed (118 MB) and the original (237 MB) checkpoint are **bit-identical** |
| wall time / peak RSS | 79 s / 3.8 GB slimmed, 68 s / 3.8 GB original (4 CPU cores, torch 2.14.1 CPU) |
| protocol | `hello` → `progress` → `artifact` (with SHA-256) → `result` (device, labels) → `done ok`; MOOSE's banner and Rich output stayed in the log |

The phantom is geometry, not anatomy; the labels MOOSE found on it are not
judged. Anatomical plausibility and MPS-vs-CPU agreement are S1 steps 3–4
on the Mac.

## On the Mac

Prerequisites: Apple Silicon, macOS 14+, Xcode 16+, `brew install xcodegen uv`,
for S3 a paid Apple Developer account. Use only public or synthetic data.

### S1 — MOOSE on MPS from the bundle layout

```bash
make test-worker                       # all green first
make runtime                           # ~3 GB download once, then cached
make models MODELS="clin_ct_organs"    # weights at build time
make licenses
```

1. Self-Test with inference, outside the app, against `build/`:
   `Scripts/run_selftest.sh clin_ct_organs`.
   Go: the last line is `done` with `ok`; the `result` line shows
   `"device": "mps"`, `"same_grid": true` and no checksum mismatches.
2. Turn Wi-Fi off and repeat. Go: identical result, no `model_not_in_bundle`.
3. A public CT (e.g. a TCIA collection with a licence that allows it),
   converted with the bundled dcm2niix, segmented once on MPS and once with
   `"device": "cpu"`. Record the Dice per label in `docs/benchmarks.md`.
4. Slimming: run step 3 once with `make models MODELS="clin_ct_organs --no-slim"`
   and compare. Go: bit-identical labelmaps (already shown on CPU, see above).

### S2 — the signed, sandboxed app starts the worker

```bash
make app                    # ad hoc signed, sandboxed, hardened runtime
open build/Build/Products/Release/BCOAnalyzer.app
```

1. File → Open or Create Project…, choose a new folder.
2. Add Source Folders…, choose a folder with a few public DICOM files.
3. Settings → Diagnostics → "Run with …".
4. Go, from the result shown: `read_source.ok`, `dicm_preamble`,
   `write_project.ok` all true; `sandboxed` true; `accelerator.mps_available`
   true. Record what `write_source` says (whether a read-only bookmark
   resolves read-only for the child).
5. Quit the app while a Self-Test with inference runs.
   Go: `ps aux | grep bcoa_worker` shows nothing within ten seconds.
6. Fallback if 4 fails: the app copies or converts the series into the project
   folder before a job (plan §5); record as an ADR.

### S3 — distribution

1. Developer ID: `make all IDENTITY="Developer ID Application: …"`, then
   `make dmg`, `xcrun notarytool submit … --wait`, `xcrun stapler staple`,
   `spctl -a -vv`. Note the upload size and notarisation time.
2. TestFlight: Xcode → Product → Archive with the App Store distribution
   certificate, Distribute → App Store Connect → Upload. Go: the upload passes
   validation. Watch for: Mach-O files under `Contents/Resources` (if
   rejected, move `python/` to `Contents/Frameworks` — only `BundleLayout`
   and `embed_backend.sh` change), unsigned nested code, and the
   "itms-services" check (`make verify` should have caught it first).
3. Record the decision on the runtime variant in ADR 0004.

### S4 — size and time

1. `make models` (all clinical), `make app`, `make verify` → `build/…/size-report.txt`.
2. Per model on an M1 with 16 GB: wall time and peak memory
   (`/usr/bin/time -l` around the worker) on one public CT.
3. Fill `docs/benchmarks.md`.
